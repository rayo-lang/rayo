# Skills

Every skill lives in `.agents/skills/`, where any agent finds it. `.claude/skills` links there for Claude Code.

## Where each skill comes from

- **This repo's own**: `code-comments`, `code-design`, `code-style`, `create-pr`. Edit them like any other file. Each one is self-contained: it refers only to files in its own folder, and shows its examples rather than pointing at the repo's code. It may name another skill to load.
- **Copied from [`mattpocock/skills`](https://github.com/mattpocock/skills)**: every other skill, installed with `npx skills add mattpocock/skills --agent universal` and pinned by content hash in `skills-lock.json`. Their MIT license is in `.agents/skills/LICENSE-mattpocock-skills`.

Upstream's `pr` skill is not copied: it writes a different PR body, and `create-pr` replaces it.

Claude Code's `mattpocock-skills` plugin is turned off for this repo in `.claude/settings.json`, so each skill loads once, from its copy here.

## Local edits to copied skills

These edits bring the copies in line with the project rules in `AGENTS.md` and `docs/agents/`:

- `triage/SKILL.md`: posted comments and issues carry no AI disclaimer (no-attribution rule).
- `wizard/template.sh`: the header carries no "Generated by" line (no-attribution rule).
- `ask-matt/SKILL.md`: pull requests go to `create-pr`, not upstream's `pr`.
- `domain-modeling/SKILL.md` and `domain-modeling/ADR-FORMAT.md`: a fourth condition offers an ADR only for a change of course on something that exists; a decision made while something is still being shaped goes into the thing itself, and before Rayo 1.0 no ADR is offered at all (the domain-docs rules in `docs/agents/domain.md`).
- `improve-codebase-architecture/SKILL.md`: an ADR for a rejected candidate is offered only when `domain-modeling`'s test passes, so it follows the same rules.

Edit a copied skill only to bring it in line with a project rule, and record the edit in this list.

## Updating the copied skills

`npx skills update` re-copies every skill from upstream and silently overwrites the local edits.

1. Run `npx skills update -p -y`.
2. Re-apply every edit in the list above; `git diff .agents/skills` shows each one reverted.
3. Check the new upstream text against the project rules in `AGENTS.md` — attribution, branch names, PR bodies — and add an edit to the list for each new conflict.
4. To take a skill upstream added, run `npx skills add mattpocock/skills --agent universal -y -s <name>`, then repeat step 3 for it.

**Done when:** `git diff .agents/skills` shows only upstream's changes, and every listed edit is in place.
